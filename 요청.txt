#### A. `core/engine.py` (엔진 안정성 및 피드백 강화)
현재 `print()` 문으로 디버깅 정보를 출력하고 있어, GUI 환경에서 로그 확인이 어렵고 진행 상황을 알 수 없습니다.
1.  **로깅(Logging) 시스템 도입:**
    *   `print()` 함수를 모두 Python 표준 `logging` 모듈로 대체하세요.
    *   `setup_logging()` 함수를 추가하여 파일(`app.log`)과 콘솔에 동시에 로그를 남기도록 설정하세요.
    *   정보는 `logging.info`, 오류는 `logging.error`, 디버깅 정보는 `logging.debug`로 구분하세요.
2.  **진행률 콜백(Progress Callback) 추가:**
    *   `convert`, `convert_file`, `batch_convert` 함수에 `progress_callback` 매개변수(선택적)를 추가하세요.
    *   대용량 파일 변환이나 배치 변환 시, 진행 상황(현재/전체, 메시지)을 GUI로 전달할 수 있도록 콜백을 호출하는 로직을 구현하세요.
    *   예: `if progress_callback: progress_callback(current, total, message)`

#### B. `ci-cd.yml` (배포 자동화)
현재는 빌드 아티팩트만 생성하고 끝납니다. 버전 태그(예: `v1.0.0`)를 푸시했을 때 자동으로 GitHub Release를 생성하고 파일을 업로드하도록 개선해야 합니다.
1.  **트리거 조건 수정:**
    *   `v*` 패턴의 태그가 푸시될 때도 워크플로우가 실행되도록 설정하세요.
2.  **빌드 조건 수정:**
    *   `build` 작업이 `main` 브랜치 푸시뿐만 아니라, 태그 푸시일 때도 실행되도록 `if` 조건을 수정하세요.
3.  **릴리스(Release) 작업 추가:**
    *   `build` 작업이 완료된 후 실행되는 `release` 작업을 추가하세요.
    *   `softprops/action-gh-release` 액션을 사용하여, 태그 푸시일 경우 자동으로 릴리스 노트를 생성하고 빌드된 파일(exe, zip)을 업로드하도록 작성하세요.

나는 이 프로젝트의 안정성을 높이기 위해 다음 3가지 작업을 우선적으로 진행하고 싶어. 이에 대한 구체적인 코드 예시와 가이드를 작성해줘.

1. **GUI 테스트 자동화 (pytest-qt 도입):**
   현재는 수동으로 print를 찍어가며 테스트하고 있어. `pytest-qt`를 사용하여 메인 윈도우(MainWindow)나 변환 페이지(ConvertPage)의 위젯 동작을 테스트하는 코드를 작성해줘. (예: 입력창에 텍스트 설정 후 설정 객체에 반영되는지 확인)

2. **백그라운드 작업 처리 (QThread/QRunnable):**
   대용량 로그 파일을 변환할 때 GUI가 멈추는(Freezing) 현상을 막고 싶어. 변환 로직(`ConverterEngine`)을 별도 스레드로 분리하고, 진행률(Progress Bar)을 메인 스레드에 업데이트하는 패턴을 PySide6 코드로 보여줘.

3. **상용 배포를 위한 구조 조언:**
   `pyproject.toml`을 기반으로 코드를 패키징하고, GitHub Actions를 통해 테스트를 자동화하려면 어떤 설정 파일이 추가로 필요한지 알려줘.

위 요구사항에 맞춰서 바로 적용할 수 있는 코드 스니펫과 설명을 부탁해.
2. 테스트 및 품질 보증 (QA)
현재 test_gui_bugs.py와 test_engine.py가 있지만, 상용급은 더 체계적이어야 합니다.

GUI 테스트 자동화 (pytest-qt 도입):
현재 test_gui_bugs.py는 main을 실행해서 프린트로 찍어보는 방식입니다. 이는 CI(지속적 통합)에서 돌리기 어렵습니다.
pytest-qt를 사용하여 GUI 이벤트를 시뮬레이션하고 결과를 검증하는 "진짜" 자동화 테스트로 변환하세요.
엣지 케이스(Edge Case) 방어:
대용량 파일: 10MB가 넘는 거대한 HTML 로그를 넣었을 때 앱이 멈추지 않는지 테스트하세요.
깨진 파일: 태그가 닫히지 않은 HTML이나 인코딩이 깨진 파일을 넣었을 때 앱이 꺼지면 안 됩니다. "파일을 읽을 수 없습니다"라는 팝업을 띄우고 우아하게 처리해야 합니다.
3. 아키텍처 및 코드 품질
test_gui_bugs.py에서 sys.path.insert를 사용하는 것은 임시방편입니다. 프로젝트 구조를 단단하게 만들어야 합니다.

패키징 구조 개선:
sys.path 해킹 대신 pyproject.toml이나 setup.py를 사용하여 프로젝트를 정식 패키지로 설치 가능한 구조로 만드세요.
설정 관리 (Config Management) 강화:
ConfigManager가 딕셔너리를 직접 다루는 것으로 보입니다. Pydantic 같은 라이브러리를 사용해 설정 데이터의 타입 검증(Validation)을 수행하면, 설정 파일이 깨졌을 때 앱이 비정상 종료되는 것을 막을 수 있습니다.
스레딩 (Threading/Concurrency):
변환 작업이 오래 걸릴 때 GUI가 "응답 없음" 상태가 되면 안 됩니다. QThread나 QRunnable을 사용하여 변환 로직을 백그라운드로 빼고, 메인 스레드에서는 프로그레스 바만 업데이트해야 합니다.
